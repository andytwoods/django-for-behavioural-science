*[slugs]: Short, URL-safe labels made only of letters, numbers, hyphens and underscores. The study "Flanker task" gets the slug "flanker", which is what puts it at /study/flanker/.
*[view]: The Python function that runs when someone visits a URL. It receives the request, works out what to send back — usually by looking something up in the database and rendering a template — and returns it. Other frameworks call this a controller or a handler; Django calls it a view, and they all live in views.py.
*[views]: The Python functions that run when someone visits a URL. Each receives the request, works out what to send back — usually by looking something up in the database and rendering a template — and returns it. Other frameworks call these controllers or handlers; Django calls them views, and they live in views.py.
*[CSRF]: Cross-site request forgery: the trick where another website quietly gets your browser to send a request to a site you are logged in to, riding on the cookies your browser attaches automatically. Django's defence is a secret token it puts in the page and demands back with every POST — another site can make your browser send a request, but it cannot read our page to find the token.
*[cookie]: A small piece of data a website asks your browser to store and send back on every later request to that same site. It is how a site recognises you between one page and the next; Django uses one to carry the CSRF token, and another to remember that you are logged in.
*[cookies]: Small pieces of data a website asks your browser to store and send back on every later request to that same site. They are how a site recognises you between one page and the next; Django uses one to carry the CSRF token, and another to remember that you are logged in.
*[template]: An HTML file with placeholders in it. Django renders it by filling those placeholders from the data a view hands over, then sends the result to the browser. Templates live in a templates/ folder inside your app.
*[templates]: HTML files with placeholders in them. Django renders one by filling those placeholders from the data a view hands over, then sends the result to the browser. They live in a templates/ folder inside your app.
*[model]: A Python class describing one kind of thing you want to store, with one field per piece of data. Django turns it into a database table for you, and each instance of the class is one row in that table. Models live in models.py.
*[models]: Python classes describing the kinds of thing you want to store, with one field per piece of data. Django turns each one into a database table for you, and each instance is one row. They live in models.py.
*[shared namespace]: One common set of names used by several places. Here, static files from every app are looked up by the same relative path, so two files called jspsych.js would claim the same name unless their app folders make the paths unique.
